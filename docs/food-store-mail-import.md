# 食のブランド館 ABCメール取り込み

2026-10-04: 道の駅あいづのABC分析表は、食のブランド館分析 `/food-store-analysis` の `food_store_sales` に保存する。店舗分析の `brand_store_sales` には保存しない。旧 `/api/brand-store/mail-import` は正しい食分析APIの互換入口に変更した。

`POST /api/food-store/mail-import` は既存の専用連携Bearer認証を使用する。受信アカウント・経理送信元・ABC件名・対象年月・月全期間のファイル名と帳票日付・添付SHA256を検証する。認証情報やメール本文はログに出さない。

CSV（UTF-8/Shift_JIS）と単一シートXLSXを決定的に読み取る。数式・上限超過・空JAN・指数表記・保存時に衝突するJAN・不一致の金額は確認待ちにする。全行をJAN単位で集約する。同名の別JANをまとめず、仕入先・部門・販売数・金額・値引・原価・粗利・単価と帳票の順位/比率/ランクを保持する。同JANで異なる商品情報は拒否し、異なる元行の順位/構成比/累計比/ランクを推測しない。粗利率は合算後に再計算する。

SQL `import_food_store_mail` が食JANマスターだけからカテゴリーを引き、未登録JANのみ補完し、既存カテゴリーや独自粗利率を上書きしない。月データ、元行、取り込み証跡を同一トランザクションで保存する。既存月の異なるデータは置換せず、同じ内容の再送は同一取り込みIDを返す。現在の全保存列・全商品の一致を再検証するので、後から改変/削除されたデータを取り込み完了扱いにしない。

成功結果は `destination: "food-store-analysis"` と `destinationTable: "food_store_sales"` を固定で返す。呼び出し元は両方と月、ハッシュ、元行数、商品数、金額、数量、原価、粗利を確認してから受領返信する。旧店舗取り込み証跡は食分析の完了根拠として使用しない。過去の誤投入の削除は別の照合・バックアップ付き復旧手順で実施し、このAPIは店舗データを削除しない。

検証: `node scripts/test-food-store-mail-import.mjs`、既存ブランドparser regression、型/ESLint/security/build。SQL検証用 `scripts/apply-food-store-mail-import-migration.mjs` は既定ROLLBACKで権限、再送、全保存列改変、JANカテゴリー、原価・値引合算、拒否、原子性を確認する。`--apply` は追加migrationのみcommitする。実添付検証は `--fixture` にローカル保管ファイルを指定し、Gitへ保存しない。
