# 商品ABCD分析

2026-09-19導入。画面 `/web-sales/abcd`、API `/api/web-sales/abcd`。
WEB販売ダッシュボードの「商品ABCD分析」から開く。

## 運用
- ECごとに公式の商品別分析CSVを取り込み、列の対応・期間・集計範囲・分母と分子を確認してプレビュー後に保存する。UTF-8とShift_JISに対応。
- 共通ヘッダー例: 商品ID,商品名,アクセス数,注文件数,売上金額,利益,状態。状態は通常・新商品・欠品。売上と利益は任意。欠測は空欄、実測ゼロは0。
- Amazonの数量/セッション、訪問者に対する注文件数、PVに対する注文件数等を別の指標として保存。率の列を購入件数に指定しない。商品ページの分母を複数SKUへ複製しない。
- メルカリの店舗全体訪問者数は商品別分析に使用不可。BASEはWeb/Pay IDの範囲を揃える。
- 数量0商品も保持。最低アクセス（初期100）未満・欠測・新商品・欠品は保留。
- 自動基準は判定対象2商品以上のアクセス中央値と、分子合計/分母合計。購入率基準が0になる場合は自動判定しない。手動基準も設定可能。
- A=アクセス高/率高、B=高/低、C=低/高、D=低/低。閾値以上を高として扱う。
- 保存時点の条件・ルール・結果は固定。ファイル名だけ変えた同一内容も重複登録しない。再計算したい場合は異なる条件で保存。
- 比較は同EC・指標・範囲・取得範囲・最低アクセス・ルールで、月全体同士または同じ日数の過去期間のみ。相対基準が変わると分類も変わるため、比較先の基準を表示。
- 改善の実施記録は同ECの過去分析分も表示（新しい実施日から最大1000件）。Excelは全商品・条件定義・改善履歴に、収益総合評価・収益計算条件を加えた5シート（収益取得時）。

## 実装・権限
- 決定的な分類と入力検証: lib/web-sales-abcd/model.ts
- CSV読込・列対応: lib/web-sales-abcd/csv.ts
- スナップショットJSONを1回のINSERTで保存。content_hash一意制約で競合も二重登録を防ぐ。
- APIは既存WEB分析と同じ管理者セッションを要求。新テーブルはRLS有効、anon/authenticatedへの権限なし、service_role経由のみ。
- 原始CSV全列・顧客情報は保存しない。選んだ商品指標のみ保存する。
- 既存売上取込・原価・広告設定・Bridge契約を変更しない。今回の取得はCSV取込で、EC管理画面からの自動収集は未実装。

## 検証
`npm run test:web-sales-abcd` / `npm run test:web-sales-abcd-migration` / `npm run predeploy`

ローカルbuildでは正しいNEXTAUTH_URLを設定する。既存の全体TypeScript検査には今回対象外のエラーがあり、新規ファイルの診断がないことを別途確認。

## 月初連携（2026-09-19）

全月のAmazon・楽天・Yahoo売上BridgeはABCD元帳票も送信する。Amazonは数量/セッション、Yahoo・楽天は件数/訪問者。楽天は追加のtraffic.original.csvが必要。Yahooは全日CSVの照合を先に行う。商品・数量・金額を照合してスナップショットを保存し、失敗時は売上が登録済みでも確認待ちを返す。退店済み3店は定期売上・精算・再試行から除外（履歴は保持）。BASEは従来通り。

8月Amazon126商品は再利用確認済み。楽天アクセス帳票とYahoo全月CSVはログイン済み管理画面待ちで未検証。

## 収益を含めた総合評価（2026-09-20）

- 従来の保存済みアクセスABCDは変更せず、月次販売集計・保存原価・広告費・EC精算費用から収益A/B/C/D・赤字・保留を追加。API取得時に再計算し、総合画面/詳細の再計算ボタンから最新値を取得する。月初Bridgeの取込結果にも自動適用。再インポート・DBマイグレーション不要。
- 売上は `web_sales_summary` の保存単価×販売点数、BASEは保存売上金額を優先。原価は `unit_cost_ex_ec` のみで、未取得を現在の商品マスター値や0で補わない。アクセス帳票の売上/件数と月次販売集計は別集計で、混ぜない。
- 商品は安定ID対応または既存の名称対応の一意一致だけで接続。推測マッチなし。同じ商品IDに複数掲載がある場合は二重計上回避のため保留。
- EC費用は同ECの保存売上比、直接広告費は同EC・シリーズ内保存売上比、Google/Meta/other共通広告は同シリーズ全EC保存売上比で配分。過去の退店EC売上も当月の共通費分母に残す。売上のない広告シリーズは未配分費として明示。
- 直接広告は従来EC利益集計に合わせ広告集計と精算書の大きい方を採り、足し合わせない。広告取込完了の証拠がない媒体は0にせず保留。全費目があり確定済みまたは明示的な概算の精算だけ収益分類する。一部精算の参考利益は表示するが分類保留。
- 対象は同じ全月期間のみ。売上0、新商品、欠品、未取得は保留。通常・売上正・計算可能な2商品以上から売上中央値と加重平均利益率（下限0%）を算出し、売上高/利益率高=A、高/低=B、低/高=C、低/低=D。赤字は独立。利益0を高収益としない。対応候補にアクセスABCDも反映。
- 全て商品別配分の推計。会社全体の営業利益/純利益ではない。画面の円表示は四捨五入、判定とExcelは丸め前。収益の更新日時・ルール・全配分条件をExcelに含む。
- 実装: `lib/web-sales-abcd/finance.ts`, `finance-server.ts`, `components/web-sales-abcd-finance.tsx`。管理者認証は既存APIを継承。収益取得エラー時も保存済みアクセス分析は表示可能。
- 検証: `npm run test:web-sales-abcd-finance`（配分保存、広告重複防止、欠損、一部費用、期間、ID重複、赤字/境界、従来判定不変）、既存ABCD/月次テスト、対象型検査・lint、predeploy。

## 分類別の対応補足（2026-09-20 訂正）
優先事項の独立カードを撤去し、総合ダッシュボードとEC詳細のA/B/C/D・赤字・保留カード内に、その分類で何をすべきかを太字で常時表示。アクセス分類と収益分類で対応文を分離。判定・DB・取込ロジックは変更しない。
