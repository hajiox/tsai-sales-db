# 商品ABCD分析

2026-09-19導入。画面 `/web-sales/abcd`、API `/api/web-sales/abcd`。
WEB販売ダッシュボードの「商品ABCD分析」から開く。

## 運用
- ECごとに公式の商品別分析CSVを取り込み、列の対応・期間・集計範囲・分母と分子を確認してプレビュー後に保存する。UTF-8とShift_JISに対応。
- 共通ヘッダー例: 商品ID,商品名,アクセス数,注文件数,売上金額,利益,状態。状態は通常・新商品・欠品。売上と利益は任意。欠測は空欄、実測ゼロは0。
- Amazonの数量/セッション、訪問者に対する注文件数、PVに対する注文件数等を別の指標として保存。率の列を購入件数に指定しない。商品ページの分母を複数SKUへ複製しない。
- メルカリの店舗全体訪問者数は商品別分析に使用不可。BASEはWeb/Pay IDの範囲を揃える。
- 数量0商品も保持。最低アクセス（初期100）未満・欠測・新商品・欠品は保留。
- 自動基準は判定対象2商品以上のアクセス中央値と、分子合計/分母合計。購入率基準が0になる場合は自動判定しない。手動基準も設定可能。
- A=アクセス高/率高、B=高/低、C=低/高、D=低/低。閾値以上を高として扱う。
- 保存時点の条件・ルール・結果は固定。ファイル名だけ変えた同一内容も重複登録しない。再計算したい場合は異なる条件で保存。
- 比較は同EC・指標・範囲・取得範囲・最低アクセス・ルールで、月全体同士または同じ日数の過去期間のみ。相対基準が変わると分類も変わるため、比較先の基準を表示。
- 改善の実施記録は同ECの過去分析分も表示（新しい実施日から最大1000件）。Excelは全商品・条件定義・改善履歴の3シート。

## 実装・権限
- 決定的な分類と入力検証: lib/web-sales-abcd/model.ts
- CSV読込・列対応: lib/web-sales-abcd/csv.ts
- スナップショットJSONを1回のINSERTで保存。content_hash一意制約で競合も二重登録を防ぐ。
- APIは既存WEB分析と同じ管理者セッションを要求。新テーブルはRLS有効、anon/authenticatedへの権限なし、service_role経由のみ。
- 原始CSV全列・顧客情報は保存しない。選んだ商品指標のみ保存する。
- 既存売上取込・原価・広告設定・Bridge契約を変更しない。今回の取得はCSV取込で、EC管理画面からの自動収集は未実装。

## 検証
`npm run test:web-sales-abcd` / `npm run test:web-sales-abcd-migration` / `npm run predeploy`
DB適用: `npm run apply:web-sales-abcd-migration`。環境変数DATABASE_URLが必要。
ローカルbuildでは正しいNEXTAUTH_URLを設定する。既存の全体TypeScript検査には今回対象外のエラーがあり、新規ファイルの診断がないことを別途確認。

## 月初連携（2026-09-19）
