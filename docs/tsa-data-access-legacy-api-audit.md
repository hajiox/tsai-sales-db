# 既存レシピ API の認証整理（2026-10-07）

専用データ接続の制限を既存 API から回避できないよう、既存 UI 用 API に管理者 NextAuth セッションの検証を追加した。書込みは同一 Origin を要求し、Origin が省略される既存ブラウザーでは同一 Origin の Referer で確認する。両方が無い書込みは許可しない。独自の正規トークン認証がある Bridge・レビュー取得の経路は変更していない。

対象はレシピ一覧・詳細・登録更新・入出力・版履歴・マスター操作・カテゴリ・食材紐付け・重複整理・飲食レシピ・見積・JAN・印刷ログ・商品/OEM/卸紐付け・画像・DB使用状況・開発文書。既存の成功レスポンスと業務処理は保持する。重複整理の `auto_cleanup` は匿名の自己 HTTP 呼出しをやめ、認証済みリクエストで内部処理を再利用する。

## 旧画像一括取込スクリプトの移行

`scripts/recipe-web-images/backfill.mjs`、`backfill-shared-folder.mjs`、`cleanup.mjs` は `/api/recipe/web-images` を認証なしで利用していた。これらを今後実行する場合は、認証済み管理者による手順、または用途・対象・期限を限定した画像取込 API へ移行する必要がある。移行まで匿名アクセスを復活させない。専用データ接続の初版は画像取込・削除を公開していないため、そのトークンを旧画像 API に付けるだけでは利用できない。

本変更では旧スクリプトを自動実行せず、DB・画像の取得登録・削除も実行していない。管理者 Cookie や Supabase 管理キーを他 Codex に配布する代替策も採らない。

## 検証

`scripts/test-recipe-request-auth.cjs` は全対象 handlers の匿名・他アカウント・別 Origin の拒否と、本文解析/DB 到達前の判定を検証する。認証済みの既存入力検証と重複整理の内部読取も mock で確認する。`scripts/test-data-access-admin.cjs` は専用接続の発行、対象限定、失効、変更案の承認、管理者識別、トークンの非再表示を実データを変更せずに検証する。

NextAuth セッションが有効な管理者に限り、自身が HS256 署名した Supabase JWT を署名検証し、期限まで 1 日以内の場合だけ 30 日の JWT に更新する。匿名 SELECT 閉鎖後も、長期利用中の管理者が別系統の JWT 期限だけでデータ取得不能にならないための対応。不正署名・別アルゴリズム・別アカウント・不明な NextAuth ユーザーは更新しない。NextAuth 自体の期限・Google 許可アカウント・セッションユーザーは変更しない。`scripts/test-auth-supabase-token-refresh.cjs` で発行、更新境界、署名と識別の拒否、セッション維持を確認する。
