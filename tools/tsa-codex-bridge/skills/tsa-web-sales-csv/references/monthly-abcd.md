# 月初のABCD用アクセス取得

対象はAmazon・楽天・Yahooの暦月全期間。売上取得と一緒に実行し、中間（1〜15日）は追加取得しない。TikTok Shop・Qoo10・メルカリは退店済みのため定期取得しない。BASEも月次は売上取得と一緒に [商品別画面データ](base-abcd.md) を取得する。

- Amazon: 既存の子ASIN別「売上・トラフィック」原本を使う。`セッション数 - 合計`と`注文された商品点数`を保持する。数量率であり注文件数のCVRではない。
- Yahoo: 商品分析原本の`訪問者数`と`注文数合計`を保持する。同期間の全体分析・日別CSVと数量・金額が全日一致することが必須。2026年8月の古い保存CSVは8月31日分が欠落しているため、そのまま再利用しない。
- 楽天: 売上CSVにはアクセスがないため、RMS/R-Karteの公式商品別アクセス帳票を同期間・全端末・税込で追加取得する。画面で会津ブランド館、開始日・終了日、商品管理番号単位を確認する。帳票には`商品管理番号`・`商品名`・`アクセス人数`・`売上件数`・`売上個数`・`売上`が必要。現在の画面で列定義を確認し、別定義・不足・不明なら具体的な列名と理由を報告して停止する。PVをアクセス人数に置き換えない。アクセス帳票の原本を`rakuten-<開始日>_<終了日>.traffic.original.csv`として作業フォルダに保存し、source_filesに含める。Bridgeが売上帳票との商品番号・金額・合計を照合する。

売上0の商品も原本に残す。欠落を0で埋めない。率からアクセスを逆算しない。広告クリック数・店舗全体アクセスで商品アクセスを代用しない。原本を編集して列名や値を合わせない。列変更時は運用結果に記録し、パーサー修正が必要な確認待ちにする。

Codexは取得とローカル検証まで。共有保存・認証付きTSA取込・ABCDスナップショット作成はBridgeとサーバーが実行する。ABCD保存が失敗した場合は売上取込済みでも全体を完了にしない。同じデータの再実行はスナップショットを重複作成しない。

## 2026-09-19 実帳票で確認した例外
- Yahooの訪問者数「2未満」は非公開の少数値。原本を変更せず、TSAがその商品のアクセスを不明・判定保留として保存する。他の商品は分析を継続し、0や1へ推測変換しない。
- 楽天の取得経路はR-Karte「アクセス・流入分析 → 商品ページ」 `/access/item`。月次で対象月を始点・終点の両方に指定し、全端末・全商品CSV・すべての項目・全件を選ぶ。UTF-8原本の表示期間は「YYYY年MM月からYYYY年MM月」。売上は `/realtime/item` から同時点で月次・全端末・税込・全件を取得する。保存済み売上と差がある場合、元ファイルを退避した上で再取得した帳票同士を照合する。
