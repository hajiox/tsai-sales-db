# BASE 月次ABCD

売上CSVとは別に、指定された暦月の商品別データを取得する。売上CSVが検証済みなら再ダウンロードせず、original/preparedをジョブ作業フォルダへコピーし、不足しているABCD原本だけ取得する。

通常のログイン済みChromeで会津ブランド館を確認し、`https://admin.thebase.com/shop_admin/data/items`（データ → 商品別）を使う。「月」を選び、対象年月を選択する。「先月」はPCの当月とジョブ対象月を照合できる場合だけ使用する。直近30日は暦月ではない。日付・ショップを確認できなければoperator wait。

2026-09-19確認: 1ページ50件。ページ番号を1から最終まで順に確認し、最終ページの次ボタンが無効になったことを確認する。読込中に空行を収集しない。商品ID（リンク末尾）、商品名、閲覧数、お気に入り数、注文数、注文率を表示DOMから取得する。売上0/閲覧0も残す。リンクがない商品は`unlinked:<表示商品名>`を識別子とし、推測で他商品へ結び付けない。重複や50件未満の中間ページは取得失敗として扱う。ページ構造が変わったら現行の表示を確認して判断する。

商品別注文数は注文**点数**、閲覧数はWeb/Pay ID合算のPV。公式ヘルプ: https://help.thebase.in/hc/ja/articles/360000184862 。画面の注文率から件数を逆算しない。売上CSVは発送済み・種類コード単位で、商品別分析とは集計範囲が異なるため、金額や数量を合わせて書き換えない。

取得した表示データをUTF-8の`base-<開始日>_<終了日>.traffic.original.json`としてジョブ作業フォルダへ保存し、source_filesに含める。JSONは次の契約（例の値を使い回さず実測値を記録）:

```json
{"schemaVersion":1,"channel":"base","shop":"会津ブランド館","source":"https://admin.thebase.com/shop_admin/data/items","start":"YYYY-MM-01","end":"YYYY-MM-DD","lastPageVerified":true,"pages":[50,10],"rows":[{"key":"商品IDまたはunlinked:商品名","name":"表示商品名","values":["閲覧数","お気に入り数","注文点数","画面の注文率%"]}]}
```

`pages`は各ページの実測行数、`rows`は全行。最終ページ未確認ならlastPageVerifiedをtrueにしない。最大100ページ/5,000商品、再試行は同じ読込失敗ページ1回まで。権限・認証待ちは再試行しない。原本生成には取得済みデータのローカル保存だけを行い、外部へ送信しない。ブラウザーAPIはcua_replが返す現行ドキュメントの範囲で利用できる。画面で取得できた事実を保存し、hidden stateや非公開APIを使わない。

Bridgeが共有フォルダへの保存と認証付き取込を行う。サーバーが期間、ページ件数、商品ID重複、数値を検証し、注文点数/PVの参考数量率として保存する。金額は未取得。既存と同じ入力は重複作成しない。ABCDが不足/不正なら売上処理が成功しても全体はneeds_reviewとなる。

## 取得データをローカルへ保存する補助
ブラウザーの表示DOMから全行をcua_repl変数へ取得した後、長いJSONをツール出力へ繰り返し表示する必要はない。必要なら次の付属スクリプトをexecで起動する。
`node <Skill>/scripts/save-base-abcd.mjs --out <作業フォルダのtraffic.original.json絶対パス> --start <開始日> --end <終了日>`
表示された一回限りの127.0.0.1 URLを通常Chromeの一時タブで開き、取得済みのJSON文字列をtextareaへ入力して保存ボタンを押す。ブラウザーの現在のツールAPIだけで行う。保存成功を確認後、一時タブを閉じる。サーバーは保存後に終了し、3分で失効する。既存原本は上書きしない。これは取得済み商品のローカル保存だけで、認証情報や顧客データを渡してはならない。初回ページ読取時に返されたブラウザードキュメントが提供するread-only DOM評価で商品行を収集し、ブラウザー内状態や非公開通信は使用しない。
