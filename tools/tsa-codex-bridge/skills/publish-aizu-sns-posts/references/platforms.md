# 公式SNS操作経路（2026-09-12更新）

この資料は操作の候補であり、固定セレクタではない。画面上の現在の意味と対象アカウントを優先する。

現在のアカウントが異なる場合、公式アカウント切替一覧から固定された `expected_account` と完全一致するログイン済みアカウントを1回だけ選ぶ。Xではサイドバー下部のプロフィールメニュー、Instagramではアカウント切替、Threadsでは公式のプロフィール切替を確認する。切替後のハンドルを再確認してから作成する。表示名やアイコンだけで対応を推定せず、候補不在・認証要求・未確認は停止する。Meta Business Suiteでも指定Instagramへの紐付けがなければ停止し、アカウント連携や設定変更は行わない。

## X

- 2026-09-16実画面確認: 投稿欄の丸い残り文字数メーターも `role=progressbar` を持つ。隣接する「残り…文字」とDOM/スクリーンショットで文字数表示だと確認できたものを、アップロード/送信中とは判定しない。`role=progressbar` の存在や `aria-valuenow=1` だけで停止判断しない。背景タイムラインの「新しいポストを表示」も今回の投稿成功通知ではない。送信中・成功・エラーは投稿欄の実際の表示と操作後の変化から区別し、不明なら再押下しない。
- Draft.jsの空行は `innerText` が改行文字を返す場合がある。各 `data-block="true"` の `textContent` をLFで連結して固定本文と比較し、空行を二重に数えない。

- 公式ホスト: `https://x.com/`
- 確認済み入口: `https://x.com/home`
- 確認済み表示: `ポスト本文`、`画像や動画を追加`、`ポストする`
- X側のカレンダー予約は使わない。日時制御はTSAの予約キューが担当する。
- Xの投稿欄はDraft.jsであり、複数行本文を`fill`すると改行が消え、URLと次行のハッシュタグが結合することがある。空の投稿欄へ本文を一括投入せず、LFで分割した各行を`type_text`し、元の改行ごとに`press_key Enter`を1回使う。空行はEnterだけで作る。
- 画像添付前と送信直前に、投稿欄の`data-block="true"`を画面順に読み、その本文をLFで連結した値が固定済み`post_text`と完全一致することを確認する。URLとハッシュタグが同じリンクになった状態は不一致である。不一致時は`Control+A`→`Backspace`で全消去し、同じ行単位入力を1回だけ再実行する。再び不一致なら送信しない。
- 画像プレビューの描画と処理が終わり、進捗表示が消えて「ポストする」が有効になってから押す。押下直後は必ず`wait_for`をtimeout 45000で実行し、成功通知または入力欄消去を待つ。即時のsnapshotや`evaluate_script`だけで待機を済ませない。
- 最初の45秒待機後も同じ固定本文・画像1枚・有効な新しい投稿ボタンが残り、処理中・成功・エラー表示が一度もない場合だけ、送信自体が発生しなかったものとして同じ編集画面で2回目を許可する。2回目も直後に`wait_for`をtimeout 45000で実行する。2回目の判断前にプロフィールへ移動すると下書きが破棄されるため、プロフィール確認は入力欄消去、成功表示、または2回目の待機完了後に限る。合計2回までとし、送信結果が不明ならそれ以上押さない。

## IGストーリー

### 写真編集の文字・スタンプ配置（Bridge 1.9.95以降）

- Metaの文字枠はtextareaの上に透明な移動要素を重ね、選択時にDOM要素を作り直す。textareaを直接fillするだけでは編集結果に反映されない場合がある。最新DOMで文字枠内の `div[data-interactable]` を確認してクリックし、フォーカスがtextareaに移った後、`type_text` で固定本文を入力する。必要ならEnd→Space→Backspaceで編集イベントを確定し、値が固定本文と一致することと「適用」が有効であることを確認する。
- 移動は `drag` の `from_uid` に最新の透明な移動要素（verbose snapshotのgeneric）を指定し、`deltaX` / `deltaY` に現在の画像枠と文字枠の矩形から求めたCSSピクセル移動量を渡す。`to_uid` は省略できる。Bridgeのドラッグ補正はMetaのStory編集ダイアログだけで有効で、選択前に座標を確定して実マウスを段階的に動かす。JavaScriptの合成MouseEvent反復、CSS変更、React内部状態の書換えは使用しない。
- サイズ変更は可視の `resize` ボタンの最新uidから同じdragで少量ずつ行い、毎回矩形・font-size・全文表示を再確認する。縮小後の再拡大でも文字サイズが戻らない場合があるため、極端に縮小しない。画像全体が331px幅なら本文は原則18px以上（1080px換算約59px以上）を目安にし、画像に元からある商品名や商品を過度に覆わない配置を選ぶ。
- 文字枠の初期位置は画像外の場合がある。画像の矩形を実測し、文字枠全体を内側へ移す。textareaのscrollHeightがclientHeightを超える場合は末尾が欠けているため、読み切れる配置に直す。必要なら固定本文を句点で2つの文字枠に分けてもよいが、読順で連結した文字列を固定本文と完全一致させ、省略・言い換えはしない。
- 移動後は文字枠/スタンプの矩形が変化したことを確認する。同じ操作が反映されなければ繰り返さず原因を確認する。最後に「適用」→「編集」で再び開き、文字とリンクスタンプの位置・内容が保存されたことを確認してから公開する。

## 2026-09-11 添付経路

SNS BridgeはCodex Computer Useのfile chooserを使わず、既存Chromeへ1回だけ接続した常駐Chrome DevTools daemonをBridge内のMCP relay経由で共有し、`upload_file` を使う。媒体別セッションの開始ごとにChromeへ再接続しない。BridgeがMCPへ公開するローカル領域は対象媒体のジョブフォルダだけで、filePathは固定済み画像の絶対パス1件に限定する。Threadsで自動リンクカードが添付ボタンを隠す場合は、本文URLを保持して自動カードだけ外す。
